# 合成性能基线与复测

脚本：`python -X utf8 scripts/benchmark_policy.py --repeats 7`。使用同一台 Windows 机器、Python 3.13.2、隔离临时目录，分别生成0、100、1000、10000条已学习的合成事件。每项报告7次计时的中位数与P95；脚本不读写真实 `.positive-feedback` 目录。进程启动、状态读取、同类型全量重放、上下文序列化分别计时。工具往返和模型处理提示的延迟不在本地脚本中，标记为未测。

| 事件数 | 基线重放中位数/P95 (ms) | 更新后重放中位数/P95 (ms) | 更新后缓存上下文中位数/P95 (ms) | 完整/紧凑字符数 |
|---:|---:|---:|---:|---:|
| 0 | 0.056 / 0.056 | 0.057 / 0.064 | 0.495 / 0.561 | 1316 / 349 |
| 100 | 43.693 / 47.026 | 36.048 / 40.993 | 0.642 / 0.674 | 1710 / 540 |
| 1000 | 614.410 / 684.573 | 437.406 / 563.019 | 8.511 / 18.096 | 1706 / 540 |
| 10000 | 4062.010 / 4137.622 | 4561.124 / 6461.692 | 46.905 / 48.026 | 1711 / 540 |

10000条时，基线状态读取中位数30.511 ms、P95 33.468 ms；复测为31.867/36.907 ms。基线启动141.251/147.684 ms，复测98.034/100.519 ms；这是分开运行的样本，不能把启动差异归因于本次修改。基线上下文序列化约0.014/0.018 ms，复测约0.014/0.019 ms，均非主要开销。

缓存命中的10000条上下文样本为46.905 ms，而同次复测的全量重放为4561.124 ms；这是本地函数级对比，不含脚本启动、文件读取、工具往返或模型提示处理。1000条以上缓存键生成仍需遍历事件，因而不是常数时间。完整重放本身未被优化，10000条复测还慢于基线；不能宣称训练或写入提速。`--compact` 在该样本中把JSON字符数从1711降至540；是否减少模型端耗时未测。

回退：省略 `--compact` 恢复原有完整输出；删除状态中的派生 `context_cache` 字段后，只读 `context` 会在内存全量重放，下一次写入自动重建缓存。不要删除任务、事件、更新或参数。旧v5状态无需迁移即可读取；添加缓存后的v5仍保留原字段。此基准只证明合成输入下的本地性能，不证明真实任务验收率提升。

## 2026-09-23 首轮运行路径优化

`learn` 对没有新就绪事件且训练状态完整的情况跳过全量重放；若事件或参数摘要不一致，仍重建并恢复完整性。任务查找在重放、缓存键、质量要求和事件状态遍历期间使用一次构建的内存索引。学习新事件或替换已学习事件时，仅刷新受影响任务类型的上下文缓存。`prepare` 优先复用已验证的分类缓存。缓存和完整性摘要是派生字段，旧 v5 状态可读；首次遇到缺失的训练摘要时，空学习会重建一次。

通过 CLI 调用 `learn` 时，如果既无新就绪事件、事件状态也没有变化，且控制器身份不需更新，则不再重写状态文件。若状态发生变化或完整性需要修复，仍持久化新状态；相关行为有隔离测试覆盖。

基准脚本新增 `--tasks` 与 `empty_learn` 指标。运行 `benchmark_policy.py --sizes 100,1000 --tasks 100 --repeats 5`，在 1000 条已学习合成事件、100 个合成任务下，本地函数级中位数为：全量同类型重放 382.944 ms，空学习 2.745 ms，缓存上下文 3.902 ms。每项仅 5 次测量，不包含 CLI 状态读写、工具往返和模型耗时。这些数值说明新空学习路径避免了全量重放，不能当作整轮任务的提速百分比；完整重放仍是训练时的主要成本。

`session-context` 将只读启停查询与回答前上下文合为一次进程调用。隔离临时目录、空控制器、已启用会话下，预热一次再测 5 次的中位数为：合并命令 118.163 ms，顺序运行 `session status` 和 `context --compact` 为 245.910 ms；两者输出的指导内容经测试一致。该数字不包含 Codex 工具往返与模型处理耗时，不保证所有机器或真实任务都有相同比例收益。

## 2026-09-23 后续优化

已精简 `SKILL.md` 的重复词表与验收细节，保留入口必需规则并把细节留在按需引用文件。官方 OpenAI 文档说明 skill 被选用时会读取完整 `SKILL.md`，因此不承诺跳过必须的读取；本项减少的是单次入口文本量，而非取消压缩后的恢复。入口由约 12.4 KB 缩至约 10.7 KB（以本机文件字节数为准）。

每次控制器写入后尝试原子生成 `action-controller.snapshot.json`，只保存分类参数、已学习事件数和质量要求；读取前以原始状态文件的 SHA-256 校验。快照缺失、损坏、过期或结构不合规时，只读回退完整状态。快照不是训练权威，也不包含具体偏好；偏好仍从独立文件读取。状态写入成功但快照构建失败时，主状态仍可用，旧快照因哈希不符不会被误用。

经训练事件、参数与轨迹摘要共同校验，且新事件确实位于已学习序列末尾时，`learn` 仅训练追加事件，并增量更新受影响任务类型的缓存；其他情况完整重放。`training_trace` 作为可核查派生字段保存，旧状态首次学习可能完整重放一次。事件修订继续立刻完整重放。新增测试覆盖增量与完整重放的参数、轨迹一致性，以及轨迹篡改、快照损坏和过期回退。

隔离合成基准：1000 事件、100 任务、5 次预热后计时，中位数分别为状态读取 5.580 ms、缓存上下文计算 4.026 ms、校验并读取快照 3.183 ms；完整同类型重放 390.896 ms。快照读取与“状态读取＋上下文计算”不是完全等价的完整 CLI 计时，且增量训练耗时尚未单独定量；不能据此宣称整轮或真实任务的固定提速比例。

## 2026-09-23 调用开销优化

`session status --compact` 为启用会话返回状态及入口 SHA-256，供当前上下文判断是否需要重读入口；`session-context --for-model` 一次输出状态、SHA-256 和不重复的指导文本。结构化 `--compact` 继续可用，中文默认以 UTF-8 输出；旧消费方可显式选 `--ascii-output`。`SKILL.md` 从该轮开始时的 10,655 字节压至约 8.6 KB，细节继续按任务读取参考文件。

空学习路径把候选就绪事件检查移到分类缓存摘要之前，并复用一次训练完整性结果。新增 `batch --plan-json` 在已有成果与验收输入时执行有界、原子、幂等的记录批次；不能代替实际工作。单项状态机校验仍由原函数执行。

1000 个合成事件、100 个任务、7 次计时的函数级中位数：空学习 2.577 ms、分类缓存上下文 3.687 ms、快照读取 2.959 ms；带快照保存 78.235 ms，禁用快照的保存对照 37.987 ms。不同批次与旧数据不能直接计算固定收益；写入快照带来可测成本，目前仍保留以保障快速回答读取。真实 token、提示缓存和整轮耗时尚未测量。

## 2026-09-23 后续写入与输入开销复测

主状态改用紧凑 UTF-8 JSON 一次序列化，并从同一序列化字节计算快照关联的 SHA-256；保存不再深拷贝完整状态或再次读取主文件计算哈希。快照仍原子写入，读操作仍重新计算主文件哈希并在不匹配时回退。已有隔离测试覆盖状态读取、快照匹配、过期与损坏回退。

相同脚本、同机、1000 个合成事件、100 个任务、7 次计时：修改前带快照保存中位数 68.950 ms，修改后 19.891 ms；禁用快照对照由 36.608 ms 降至 9.663 ms。合成状态文件从 887,156 字节缩为 601,404 字节。各组为先后运行，环境波动可能影响差值；这说明本地保存路径变轻，不代表模型额度同比下降。

入口进一步从 8,593 字节缩至 7,813 字节，全局 `AGENTS.md` 启用说明也作语义等价精简。隔离空状态 CLI 输出：原紧凑 JSON 为 439 字节，`--for-model` 为 238 字节；两者分别计时的中位数为 122.592 ms 和 113.023 ms。字节数是确定性的该样本结果；未取得实际模型 token、提示缓存或账户额度的可归因用量，不能由字节比例推算。
