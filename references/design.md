# 有符号反馈刻度与统计解释

## 刻度

分数是用户指定和本设计补充的控制信号，不是满意概率，也不代表词语之间存在经心理测量验证的等距关系。

| 类型 | 词语 | 值 |
|---|---|---:|
| positive | 很好、十分感谢 | 1.0 |
| positive | 特别感谢 | 0.9 |
| positive | 不错、非常感谢 | 0.8 |
| positive | 多谢 | 0.7 |
| positive | 可以、还可以、谢谢 | 0.6 |
| evaluation | 不太满意 | -0.2 |
| evaluation | 不满意 | -0.4 |
| evaluation | 很差 | -0.7 |
| evaluation | 太差劲了、垃圾 | -1.0 |
| request | 希望你 | -0.15 |
| request | 需要你、我想、想 | -0.25 |
| request | 要求你 | -0.4 |
| request | 命令你 | -1.0 |

扩展映射（保留以上原有分值）：

| 类型 | 新增词语 | 值 |
|---|---|---:|
| positive | 基本满意 | 0.6 |
| positive | 还不错、有帮助、有用 | 0.7 |
| positive | 满意、做得不错 | 0.8 |
| positive | 很满意、很棒 | 0.9 |
| positive | 非常满意、太棒了、完全符合要求 | 1.0 |
| evaluation | 有待改进、不够好 | -0.2 |
| evaluation | 不够准确、不够完整 | -0.4 |
| evaluation | 有误、不准确、有遗漏 | -0.5 |
| evaluation | 答非所问、偏离要求 | -0.6 |
| evaluation | 很不满意 | -0.7 |
| evaluation | 完全错误、完全不符合要求 | -0.9 |
| request | 希望、我希望、能否、可否 | -0.05 |
| request | 请、请你、帮我、麻烦你、我需要、我想要、想要 | -0.15 |
| request | 务必、必须、请务必 | -0.3 |

先由模型核对请求/评价的对象与整句含义，再将所选标签交给脚本；脚本接受精确标签，不自动扫描自然语言。否定、引用、假设、反讽及重叠命中的处理遵循 `SKILL.md`。这些数值是控制信号的约定，不是语言强度的客观测量；礼貌表达不会降低明确要求的执行优先级，负面评价也不直接证明内容确有错误。

positive允许用户明确给出[0,1]内数值。evaluation和request允许[-1,0)内数值，但二者的语义绝不相同。多个命中不相加；混合类型拆成多个事件。

`positive=0` 是零强度认可，计入明确反馈，但不会改参数；任何大于0的正值都表示认可。沉默为缺失，不是0。低于先前平均分也不自动成为惩罚。

## 独立账本统计

`feedback.py` 提供轻量事件账本，用于统计而不执行任务控制器。每个事件带 `kind`，同一 `response_id + kind` 只有一个有效值；纠正追加 `replace=true` 事件并保留历史。`source_id` 全局唯一，重复相同内容幂等，重复不同内容报错。真实账本使用 `--profile MODEL_PROFILE` 写入当前工作目录的 `.positive-feedback/MODEL_PROFILE/events/`，不得写入 skill 安装目录。

`label` 是映射标签，`quote` 只保存核对过的用户原文片段；新 CLI 记录必须显式提供 `--quote`，不再自动把标签复制成原文。

每类分别统计：

```text
N_k = 有效事件数
C_k = sum(score)
M_k = C_k / N_k，N_k=0时为null
E_1 = score_1
E_n = (1-alpha)E_(n-1) + alpha score_n
```

默认 `alpha=0.2`，仅在该类型有效事件序列上递推。统计不得把request的负值解释成不满意，也不得把三类相加得出一个“总体满意度”。

控制器状态已经包含完整事件、任务、动作证据和训练重放轨迹，因此真实执行闭环应使用 `policy.py`。同一反馈不要同时写入两个系统并当作两次训练样本。

## 归因限制

- 正反馈只证明用户对明确对象给出了该强度的认可，不能证明每个动作都最优；控制器只在完成与验收证据存在时将其归因给实际动作。
- 负面评价应尽量指出方面和失败动作。笼统评价不足以决定要远离哪个操作时不训练。
- 请求词表达意图强度，不评价上一结果；即使分值为-1也只能吸引目标动作。
- 只有下一条内容与旧失败属于同一任务链时，才能作为纠正目标。
- 分数变化不是因果证据；不同任务难度、不同用户和不同类型之间不可直接比较。

## 数据与审计

事件使用UTC时间。账本文件名使用来源ID的SHA-256以帮助去重，但不是防篡改签名。控制器状态以临时文件写入并原子替换，同样不是不可篡改存储。不要记录凭据、隐藏推理或不必要的完整私密文本。

测试目录和状态文件必须与真实用户数据隔离。没有事件时，各类统计均为 `null`，不得伪造0分样本。
