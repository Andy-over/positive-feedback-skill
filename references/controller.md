# 外部任务动作控制器：数学与反向传播

## 模型范围

`policy.py learn` 训练动作控制器 `pi_phi(a | c)`；它输出任务动作建议，再由助手在明确要求和安全边界内执行。另有显式调用的 [本地检查点训练](local-model-training.md)，读取经核验的纠正成果，对独立 causal-LM 检查点运行完整反向传播并保存新检查点。两者参数、数据及触发条件不同，控制器分数变化不能冒称为语言模型参数变化。

输入 `c` 为8维：4个任务类型one-hot（writing/code/data/general）与4个布尔标志（artifact_present/evidence_required/revision_requested/output_required）。

```text
h1 = tanh(W1 c + b1)       W1:16x8,  b1:16
h2 = tanh(W2 h1 + b2)      W2:16x16, b2:16
z  = W3 h2 + b3            W3:12x16, b3:12
p_i = sigmoid(z_i)
```

共 `128+16+256+16+192+12=620` 个可训练参数。12个输出是独立sigmoid动作分数，不用softmax互斥，因为一个任务可同时需要编辑、核验与交付。这些值未做概率校准，对外不得称为成功概率或满意概率。

## 正反馈与请求信号

对已验证目标动作集合 `A+`，令 `w=|score|`：

```text
L_attract = -w * sum(i in A+) log(sigmoid(z_i))
dL/dz_i = w * (sigmoid(z_i)-1), i in A+
```

正反馈用任务真实 `actual_actions` 作为 `A+`。请求信号用本条请求的 `target_actions` 作为 `A+`。请求虽以负数存储，但仅取绝对值表示强度；损失中没有失败动作或上一回答项，因此不产生“远离上一轮”的训练语义。

`score=0` 时损失和梯度均为0，参数不变；`score=0.1` 仍产生正向吸引。缺失反馈不进入训练。

## 评价负反馈

`evaluation_mode=selection` 用于动作选择错误。设失败动作集合 `A-`、已验证修正动作集合 `A+`、`w=|score|`。对每个失败—目标动作对使用成对排序损失：

```text
L_pair = w / (|A-| |A+|) * sum(n in A-, q in A+) softplus(z_n-z_q)
dL/d(z_n-z_q) = w / (|A-| |A+|) * sigmoid(z_n-z_q)
```

梯度降低失败动作相对目标动作的logit，并提高修正动作的相对logit。它不是笼统压低上一回答，也不在没有明确目标时更新。失败动作与目标动作不得重叠。

`evaluation_mode=quality` 用于动作本身正确、执行质量不足的情况。它对已验证纠正任务的 `target_actions` 使用与请求相同的吸引损失，不降低原动作分数，允许失败动作与目标动作重叠；具体质量要求另存并在相同任务类型的预生成上下文中显示。

## 全网络反向传播

无论损失产生何种 `delta_z`，都按以下方式传播：

```text
dW3 = delta_z h2^T                 db3 = delta_z
delta_h2 = (W3^T delta_z) .* (1-h2^2)
dW2 = delta_h2 h1^T                db2 = delta_h2
delta_h1 = (W2^T delta_h2) .* (1-h1^2)
dW1 = delta_h1 c^T                 db1 = delta_h1
```

所有梯度使用更新前参数。整体L2范数裁剪：`g'=g*min(1,1/||g||)`；学习率 `eta=0.08`；更新 `phi'=phi-eta*g'`。未激活输入列在单步可能为0，因此“全网络可反传”不等于每次620个数都改变。

## 重放、纠正和可解释指标

初始化使用固定随机种子。每次学习从初始化参数开始，按有效 `learned` 事件顺序重放，保证事件纠正后旧影响可被移除。每步记录：`loss_before`、裁剪前梯度范数、裁剪比例和参数L2变化。

控制器状态格式为v5，具体诉求文件格式为v1。旧 v5 状态缺少缓存和身份字段时仍可读取；v4控制器可以读取并在下一次写操作时升级。为避免更新记录随事件数平方增长，每次更新保存完整重放轨迹的SHA-256与事件数，只内联本次新事件的逐步指标；事件修订会在旧更新上标记 `superseded_events`。按任务类型的上下文参数缓存由写入阶段重建，以有效事件摘要与缓存版本校验；只读上下文命中直接使用，失效时只在内存重放。缓存是派生数据，不是训练样本或迁移来源。

结果评估关注：必需动作覆盖率、成果是否生成、证据是否存在、验收是否通过、负反馈的目标—失败logit间隔是否增大、正向目标动作分数是否提高。语言长度或语气只能作为次要观察，不是主要成功标准。

该控制器不能证明长期偏好提升，也不能把几个离散词的值解释成真实满意概率。动作分数只是外部策略信号；明确指令必须执行，即使对应分数较低。

## 预生成上下文

`context` 只重放与当前 `task_kind` 相同的有效 `learned` 事件，再对同一任务特征分别计算重放参数和固定初始化参数的动作分数，只选择正差值最大的至多四个非必需动作。没有同类型已学习事件时不输出动作偏好。它还加入适用的具体偏好和已验证质量要求，并执行条数与字符预算。该命令不获取写锁、不创建目录或锁文件、不返回反馈原文，也不写状态。

`test_policy.py` 对吸引损失和成对损失的全部620个参数分别做 `eps=1e-5` 中心有限差分，另测0分、0.1分、请求隔离、评价目标门控、实际成果门控、验收失败重试和完整事件生命周期。
